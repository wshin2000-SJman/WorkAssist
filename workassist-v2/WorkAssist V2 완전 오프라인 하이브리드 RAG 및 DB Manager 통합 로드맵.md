기존에 수립한 오프라인 하이브리드 RAG 아키텍처에 사용자의 직관적인 데이터 통제권을 부여하는 **'DB Manager' 기능 모듈을 추가하여 고도화한 통합 개발 계획안**입니다.

WorkAssist V2의 철저한 **'기능별 모듈화(Modular Architecture)'** 원칙에 따라, 기존 파이프라인을 건드리지 않고 독립된 관리 레이어로 장착되도록 설계했습니다.

# [고도화 계획안] WorkAssist V2: 완전 오프라인 하이브리드 RAG 및 DB Manager 통합 로드맵

## 1. 시스템 아키텍처 및 모듈화 구조 (Modular Architecture)

WorkAssist V2는 각 기능이 엄격하게 분리되어 상호 의존성을 최소화합니다. 신설되는 `DB Manager`는 이미 구축된 네이티브 스토리지 엔진들과 다이렉트로 바인딩되어 데이터의 형상을 시각화하고 제어하는 **독립된 통합 관리 뷰(Admin View)** 역할을 수행합니다.

```
┌────────────────────────────────────────────────────────────────────────┐
│                        [ WorkAssist GUI 단일 앱 ]                      │
├────────────────────────────┬───────────────────────────────────────────┤
│    ▶ RAG Ingestion 모듈    │         ▶ NEW: DB Manager 모듈            │
├────────────────────────────┼───────────────────────────────────────────┤
│ * OpenDataLoader PDF 제어  │ * 지식 그래프 토폴로지 시각화 (petgraph)  │
│ * 로컬 텍스트 청킹/정제    │ * 기술 사양 데이터 그리드 CRUD (rusqlite) │
│ * 로컬 임베딩 연산 (ort)   │ * 데이터 원자적 일괄 삭제 / 무결성 검사  │
└────────────┬───────────────┴─────────────────────┬─────────────────────┘
             │                                     │
             └─────────────────┬───────────────────┘
                               ▼
            [ 로컬 삼총사 DB 저장소 (SQLite / LanceDB / petgraph) ]
```

## 2. 'DB Manager' 모듈의 핵심 기능 정의

### ① 지식 그래프 시각화 및 수동 관계 편집 (Graph Curation)

- **기능:** `petgraph`에 바이너리로 직렬화되어 저장된 부품 간의 호환성/계층 관계망을 프론트엔드 UI에 노드-링크 다이어그램 형태로 렌더링합니다.
    
- **모듈화 구현:** 프론트엔드 시각화 라이브러리(e.g., d3.js)와 Rust 백엔드를 Tauri IPC(Inter-Process Communication) 브릿지로 연결합니다. 사용자가 UI에서 마우스 드래그로 노드를 잇거나 끊으면, 백엔드의 `petgraph` 메모리 객체가 즉시 수정(`add_edge` / `remove_edge`)되고 SQLite에 안전하게 동기화 저장(Dump)됩니다.
    

### ② 기술 사양 데이터 그리드 편집 (Metadata CRUD)

- **기능:** OpenDataLoader PDF가 자동 추출하여 SQLite `Specs` 테이블에 적재한 품번별 사양 수치(전압, 토크, 크기 등)를 유저가 엑셀 형태의 데이터 그리드로 확인하고 수정하는 기능입니다.
    
- **모듈화 구현:** `rusqlite`와의 데이터 매핑을 전담하는 가벼운 CRUD 매니저를 구동합니다. 데이터의 무결성(Integrity)을 위해 수치 입력 필드에 타입 밸리데이션(숫자 변수 범위 검증 등) 레이어를 독립적으로 배치합니다.
    

### ③ 지식 데이터 독립 삭제 및 청소 (Data Purge & Clean)

- **기능:** 특정 메이커 카탈로그의 단종이나 오파싱으로 인해 데이터를 도려내야 할 때, 다른 데이터의 손상 없이 특정 영역만 안전하게 파괴(Purge)합니다.
    
- **모듈화 구현:** SQLite의 `ON DELETE CASCADE` 제약 조건을 트리거하여 메인 부품이 삭제될 때 하위 청크 텍스트가 동시에 날아가게 만듭니다. 이와 동시에 LanceDB에서 해당 `chunk_id` 목록을 배치 삭제(`table.delete`)하는 트랜잭션 래퍼 로직을 구동하여 두 DB 간의 동기화 불일치를 방지합니다.

## 3. 업데이트된 오프라인 데이터 파이프라인

`DB Manager`의 추가로 인해 사용자가 데이터를 수동으로 교정(Curation)할 수 있는 피드백 루프가 완성되었습니다.

```
[ PDF 업로드 ] ──► [ opendataloader-pdf ] ──► [ 오프라인 텍스트 및 구조화 추출 ]
                                                          │
                                                          ▼
                                            [ 로컬 삼총사 DB 인덱싱 ]
                                           (SQLite / LanceDB / petgraph)
                                                          │
                                                          ▼
                                               ┌────────────────────┐
                                               │   NEW: DB Manager  │
                                               └──────────┬─────────┘
                                                          │
                    ┌─────────────────────────────────────┴─────────────────────────────────────┐
                    ▼                                     ▼                                     ▼
     [ 지식 그래프 관계 수동 편집 ]         [ 스펙 데이터 그리드 교정/CRUD ]           [ 단종 부품 동기화 일괄 삭제 ]
```

## 4. 고도화된 단계별 개발 로드맵 (Milestones)

- **1단계: 인프라 및 사이드카 연동 (1주 차)**
    
    - WorkAssist V2 핵심 환경 구성 및 필수 크레이트(`rusqlite`, `lancedb`, `petgraph`, `ort`) 셋팅.
        
    - `opendataloader-pdf` 실행 환경 배포 패키징 및 Rust 비동기 서브프로세스(`tokio::process::Command`) 호출 아키텍처 검증.
        
- **2단계: 네이티브 하이브리드 스토리지 구축 (2주 차)**
    
    - 오프라인 RAG 작동을 위한 SQLite 메타 스키마 설계 및 LanceDB 임베디드 테이블 연동.
        
    - `ort` 엔진 기반의 로컬 텍스트 임베딩(`all-MiniLM-L6-v2.onnx`) 연산 파이프라인 완성.
        
- **3단계: NEW - DB Manager 핵심 기능 구현 (3주 차)**
    
    - `rusqlite` 바인딩 기반의 데이터 그리드 CRUD 엔진 개발.
        
    - `petgraph` 데이터의 직렬화/역직렬화(`bincode`) 프로토콜 및 UI 시각화 브릿지 연동.
        
    - 하이브리드 데이터 동기화 삭제(SQLite Cascade + LanceDB ID Delete) 매커니즘 구현.
        
- **4단계: 파이프라인 통합 및 최종 검증 (4주 차)**
    
    - RAG 주입 파이프라인과 DB Manager 간의 동시성 제어(Race Condition 방지) 및 메모리 누수 점검.
        
    - 인터넷이 전면 차단된 오프라인 환경에서의 하이브리드 검색 레이턴시(목표 50ms 이내) 벤치마크 수행 후 최종 릴리즈 준비.
